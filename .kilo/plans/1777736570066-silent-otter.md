# Feature-Sliced Design (FSD) Refactoring Plan

## Overview
This plan outlines the step-by-step refactoring of the codebase to adhere to Feature-Sliced Design (FSD) architecture. The current structure is a standard React app lacking FSD layers, with business logic scattered across pages and improper dependencies. The goal is to create a maintainable, scalable architecture with proper layer isolation and unidirectional data flow.

## Current Issues
- Missing FSD layers (app, processes, features, entities, shared)
- Business logic scattered across pages
- Cross-slice imports in pages layer (e.g., StoreOwnerOrders importing from StoreOwnerOverview)
- No proper separation of concerns
- Global contexts mixing responsibilities

## Target Architecture
```
src/
├── app/           # Global providers, routing, app config
├── processes/     # Multi-page business processes (empty for now)
├── pages/         # Page components (route definitions, composition)
├── features/      # Business features (auth, cart, orders, etc.)
├── entities/      # Business entities (user, product, order models)
└── shared/        # Reusable components, hooks, lib, UI, contexts
```

## Phase 1: Directory Structure Setup

### Step 1: Create FSD Directory Structure
Create the following directory structure under `src/`:
- `src/app/` with subdirs: `providers/`, `routing/`, `index.ts`
- `src/processes/` (empty)
- `src/pages/index.ts` (existing pages will be reorganized)
- `src/features/` with subdirs: `auth/`, `cart/`, `orders/`, `products/`, `store/`, `admin/`, `delivery/`, `marketing/`
- `src/entities/` with subdirs: `user/`, `product/`, `order/`, `store/`, `index.ts`
- `src/shared/` with subdirs: `ui/`, `hooks/`, `lib/`, `contexts/`, `index.ts`

### Step 2: Move Existing Directories
- Move `src/components/` → `src/shared/ui/`
- Move `src/hooks/` → `src/shared/hooks/`
- Move `src/lib/` → `src/shared/lib/`
- Move `src/contexts/` → `src/shared/contexts/`
- Move `src/data/` → `src/entities/` (temporary, will refactor content)

### Step 3: Update Import Paths
Update all import statements throughout the codebase to reflect new locations using absolute paths with layer prefixes (e.g., `@/shared/ui/Button`).

### Step 4: Create Layer Index Files
Create `index.ts` files in each layer directory that export the public API of that layer.

## Phase 2: Feature Extraction

### Step 5: Extract Auth Feature
Create `src/features/auth/` with slice structure:
- `model/` - auth state, types, selectors
- `ui/` - login form, user profile components  
- `api/` - authentication API calls
- `lib/` - auth utilities, JWT handling
- `index.ts` - feature exports

Move authentication logic from `src/shared/contexts/AuthContext.tsx` into this feature.

### Step 6: Extract Cart Feature
Create `src/features/cart/` with cart management logic from CartContext.

### Step 7: Extract Orders Feature
Create `src/features/orders/` with order management logic used across different user roles (admin, store owner, delivery).

### Step 8: Extract Products Feature
Create `src/features/products/` with product display and catalog logic.

### Step 9: Extract Store Feature
Move store owner specific logic from pages into `src/features/store/`:
- Store management
- Product CRUD operations
- Sales analytics
- Warehouse management

### Step 10: Extract Admin Feature
Move admin panel logic into `src/features/admin/`.

### Step 11: Extract Delivery Feature
Move delivery driver logic into `src/features/delivery/`.

### Step 12: Extract Marketing Feature
Move marketer tools into `src/features/marketing/`.

## Phase 3: Layer Refinement

### Step 13: Refactor Entities Layer
Transform `src/entities/` from mock data to pure business logic:
- Create type definitions for User, Product, Order, Store entities
- Extract business rules and validation logic
- Create entity-specific APIs that features can use
- Remove mock data dependencies from entities

### Step 14: Implement App Layer
Move global app logic to `src/app/`:
- App providers and context setup
- Routing configuration from App.tsx
- Global error handling
- App initialization logic

### Step 15: Refactor Pages Layer
Simplify pages to only handle:
- Route definitions
- Layout composition
- Feature orchestration

Remove business logic from pages, delegating to appropriate features.

### Step 16: Update Import Paths and Enforce Rules
Ensure all imports follow FSD rules:
- Unidirectional flow: shared ← entities ← features ← pages ← processes ← app
- No cross-imports within the same layer
- Features can import from entities and shared
- Pages can import from features, entities, and shared

## Phase 4: Testing and Validation

### Step 17: Update Tests
Move test files to match new structure and update imports.

### Step 18: Validate Architecture
Run static analysis to ensure:
- No circular dependencies
- Proper layer boundaries
- Unidirectional data flow
- Feature isolation

### Step 19: Final Cleanup
- Remove any unused files
- Update documentation
- Ensure all functionality works as before

## Implementation Guidelines

### Slice Structure
Each feature/entity slice follows:
```
slice/
├── model/          # State, types, business logic
├── ui/            # Components specific to this slice
├── api/           # API calls and data fetching
├── lib/           # Utilities and helpers
├── config/        # Configuration
└── index.ts       # Public API exports
```

### State Management
- Use feature-specific state management (Redux Toolkit slices)
- Avoid global state where possible
- Prefer composition over monolithic state

### Import Rules
- Use absolute imports with layer prefixes
- Implement ESLint rules to prevent forbidden imports
- Features cannot import from other features
- Entities cannot import from features or pages

## Success Criteria
- All FSD layers are present and properly structured
- No cross-slice imports in the same layer
- Business logic is isolated in appropriate features
- Unidirectional data flow is maintained
- Code is more maintainable and scalable
- Existing functionality is preserved

## Risk Assessment
- **High Risk**: Breaking existing functionality during moves - extensive testing required
- **Medium Risk**: Import path updates across large codebase - systematic approach needed
- **Low Risk**: Directory structure changes - can be done incrementally

## Timeline Estimate
- Phase 1: 2-3 days (directory setup, moves, imports)
- Phase 2: 4-5 days (feature extraction, logic refactoring)
- Phase 3: 3-4 days (layer refinement, entity refactoring)
- Phase 4: 1-2 days (testing, validation, cleanup)

Total: ~10-14 days for complete refactoring.
